# Supabase and Brevo deployment

## App credentials

The browser uses `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (or the legacy public anon key fallback). Never put a database password, Supabase secret/service key, or Brevo key in a `VITE_` variable. The project `.env` is ignored by Git; `.env.example` contains placeholders only.

## Authentication email delivery

Sign-up confirmation and password reset messages are generated by Supabase Auth. Configure a verified MENYA sender domain in Brevo, obtain its SMTP credentials (the SMTP key, not the Brevo API key), then configure Custom SMTP in Supabase Authentication settings:

- Host: `smtp-relay.brevo.com`
- Port: `587` with TLS
- Username: the Brevo SMTP login
- Password: the Brevo SMTP key
- Sender: the verified MENYA From address and name
- Keep email confirmation enabled and set the site URL plus allowed redirect URLs to the actual app domains.

The Auth settings are not stored in the browser or committed configuration. Supabase supports custom SMTP configuration in the Dashboard or Management API. Its default mail service is restricted and rate limited, so it is not the production sender. [Supabase Custom SMTP setup](https://supabase.com/docs/guides/auth/auth-smtp).

## MENYA transactional communications

The `send-communication` Edge Function sends the welcome and weekly-summary emails through Brevo's transactional email API. It verifies the caller's Supabase access token, always sends to the verified account email, accepts only fixed communication types, records per-user event keys, and never accepts HTML, sender, or recipient values from the browser. The API key stays in Supabase Function secrets. [Brevo transactional email API](https://developers.brevo.com/reference/send-transac-email).

Set these secrets in Supabase Functions settings or through the authenticated CLI:

- `BREVO_API_KEY`
- `BREVO_SENDER_EMAIL` (verified sender)
- `BREVO_SENDER_NAME` (optional)
- `APP_ORIGINS` (comma-separated exact HTTPS app origins; include local development origin only in a development project)

The Supabase runtime provides project URL and server credentials to Edge Functions. The local ignored `.env` can hold deployment inputs, but Edge Functions do not read the Vite app's `.env`; set `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, `BREVO_SENDER_NAME`, and `APP_ORIGINS` as Supabase Function secrets before deploying. Do not bulk-load `.env` into Supabase because it also contains browser configuration and database connection values. Configure `BREVO_SMTP_LOGIN` and `BREVO_SMTP_KEY` directly in Supabase Auth Custom SMTP settings; they are not Edge Function secrets. `SUPABASE_ACCESS_TOKEN` is only for authenticating the local Supabase CLI. The app calls the function after sign-in for eligible new accounts and on a user's request to email a weekly learning summary. Password reset and verification emails remain Supabase Auth emails and use its Brevo SMTP configuration.

The event claim prevents concurrent duplicate sends in ordinary retries. A process crash after Brevo accepts an email but before MENYA records `sent` can still lead to a repeat after the processing lease expires; provider delivery cannot be represented as exactly once across two independent systems.

## Deployment order

1. Review the linked project and migration history. Apply `supabase/migrations` in timestamp order to a development project and verify the RPC, RLS, and Auth flows.
2. Configure verified Brevo sender/domain, Auth Custom SMTP, redirect URLs, and the Edge Function secrets.
3. Deploy `send-communication` and test sign-up confirmation, password reset, welcome mail, and weekly summary with owned test addresses.
4. Run the same migration review and explicit deployment for production only after the development verification passes.

The repository does not contain Supabase CLI project-link metadata. Migration `202611030004_account_profiles_and_auth_audit.sql` was applied to the configured Supabase project through its session pooler and verified in the remote migration history. The new profile trigger, RLS setting, and authenticated audit RPC grant were also checked live. This deployment did not configure Brevo or Supabase Auth SMTP.
